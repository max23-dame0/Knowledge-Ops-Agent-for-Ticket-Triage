# Agent 自我改进引擎 + RAG 深化 + 评测体系升级规划（PLN-001）

> **摘要**：以「RL 思想推动 agent 持续进化」为核心愿景，规划三条并行改进线——A. 自我改进引擎（失败反思 → 经验沉淀 → 检索增强注入 → 回归门控）；C. RAG 检索深度（rerank / 相关性门控 / 查询改写 / 检索质量评测）；D. 评测体系升级（semantic grader）。目标是把项目从「可演示原型」推向「可自我迭代的企业级 Agent」，消除 demo 感。
> 状态：**draft**——规划待确认；方向 B（真实工单数据集评测）用户已在云环境执行，本文档不展开，仅在 D3 承接其产出。

---

## 1. 背景与动机

### 1.1 核心愿景（用户 2026-08-13）

「用 **RL 思想**推动 agent 持续进化」——不是训练模型（无算力、与项目"API 编排"定位冲突），而是把强化学习的核心机制落到应用层：

| RL 机制 | 本项目落点（无需梯度更新） |
|---|---|
| RLVR 可验证奖励 | 评测指标天然可验证：路由对错 / 工具调用对错 / 拒答对错 |
| 经验回放（replay buffer） | 失败案例经验池（结构化持久化） |
| 策略迭代（policy iteration） | 失败反思 → 经验注入 → 回归 → 门控接受 |
| 安全约束（constrained RL） | 安全指标（拒答/注入/幻觉）作为**硬 gate**，防 reward hacking |
| Reflexion（口头强化学习） | LLM 反思失败轨迹，产出可注入的经验条目 |

### 1.2 现状与差距（企业就绪度修复 + 外部评测之后）

| 维度 | 现状 | 差距 |
|---|---|---|
| 自我改进 | 评测是"一次性报告"：失败 → 人工分析 → 手工改规则 | 无自动化闭环，每次迭代靠人 |
| RAG 检索 | HNSW + BM25 混合检索，top_k=3 固定，L2 距离无阈值 | 无 rerank、无相关性门控、检索失败无低置信信号 |
| 分块 | chunk 固定 400/80，无语义切分 | 短问题/跨段证据召回质量受限 |
| 评测 | 规则式 5 指标 + 外部安全数据集 | 无回答质量评估（semantic grader），无检索质量指标（recall/MRR） |

### 1.3 已有基础（全部复用）

- 评测逐条结果已结构化落盘（`data/eval_results/`，含 route/tool/clarify/grounding/refusal 判定）
- 混合检索管线（chunking + embeddings + FAISS HNSW + BM25）
- 外部评测脚本 `src/evals/external_bench.py`（可重复运行）
- 企业就绪度 12 项修复（FastAPI/限流/审计/多轮会话）

## 2. 方向总览

```
                 ┌─────────────────────────────────────────┐
                 │  A. 自我改进引擎（核心，RL 思想落地）     │
                 │  eval 失败 → 反思 → 经验池 → 检索注入     │
                 │  → 回归 → 门控接受（安全硬约束）          │
                 └───────────────┬─────────────────────────┘
                                 │ 依赖 C 的检索管线做经验注入
                 ┌───────────────▼─────────────────────────┐
                 │  C. RAG 检索深度                         │
                 │  rerank + 相关性门控 + 低置信信号         │
```

## 3. 方向 A：自我改进引擎（核心）

### 3.1 闭环设计

```
┌────────┐   失败样本    ┌────────┐  经验条目   ┌────────────┐
│ offline │ ──────────→ │ 反思器  │ ─────────→ │ 经验池      │
│  eval   │  (结构化)    │ (LLM)   │            │ data/exp/   │
└────────┘              └────────┘            └─────┬──────┘
    ↑                                               │ 检索相似经验
    │  回归验证 + 门控（安全硬约束）                 ▼
    │         ┌──────────────────────────────────────┐
    └─────────│  main_agent prompt 注入（经验 few-shot）│
              └──────────────────────────────────────┘
```

### 3.2 模块与约束

| 模块 | 职责 | 关键约束 |
|---|---|---|
| 失败轨迹采集器 | 从 eval 逐条结果提取失败样本（问题/预测/期望/错误类型/轨迹摘要） | 复用现有落盘，不改 eval runner 主流程 |
| 反思器 ReflectionGenerator | 低预算 LLM 反思失败根因，产出经验条目 `{situation, action, lesson}` | **不参与路由决策**（D004 红线），只产出文本经验 |
| 经验池 ExperienceStore | jsonl 落盘 `data/experience/`，容量上限 + 去重 | 条目**禁止存原始工单 PII**，只存模式化描述 |
| 检索增强注入 | 请求 → 检索相似经验（复用 chunking/BM25/FAISS）→ 注入 main_agent | 注入是 prompt 增强，决策 owner 不变（D004） |
| 自我改进门控 | 注入后跑回归：安全指标**不得下降**（硬 gate）+ 效果指标提升才接受 | 防 reward hacking：路由涨了但拒答掉了 → 拒绝 |

### 3.3 防 reward hacking（本方向最重要的设计点）

优化目标不能是单一 route_accuracy。接受一次经验注入的条件：

1. **安全硬约束（不降即过）**：注入 60/60、Jailbreak 100/100、OOS 30/30 拒答率保持 100%，幻觉风险保持 0
2. **效果软目标（提升才接受）**：目标错误类型修复数 > 0，且总回归失败数不增
3. 不满足 → 经验条目标记 `rejected` 并降权，不再注入

## 4. 方向 C：RAG 检索深度

| 模块 | 内容 | 依赖说明 |
|---|---|---|
| C1 CrossEncoder rerank | 粗排 top_k=20 → `sentence-transformers` 的 CrossEncoder 精排 top_k=3 | **零新依赖**（同一包，本地 CPU 可跑） |
| C2 相关性门控 + 低置信信号 | 精排分数阈值；低于阈值 → 输出"未找到强证据"并引导澄清/明示弱证据 | 修复"低相关也能进 top3"的既存问题 |
| C3 查询改写 | 短查询 query expansion（规则扩展 + 低预算 LLM 改写） | 提升短 KB 问题召回 |
| C4 检索质量评测 | 构建 KB 检索评测集（query → 相关文档标注），跑 recall@k / MRR 基准脚本 | 方法论复用（血染钟楼 retrieval_quality_benchmark 同款） |
| C5 语义分块（可选） | 标题/语义段落切分替代固定 400/80 | 放在 C1-C4 之后按需做 |

## 5. 方向 D：评测体系升级

| 模块 | 内容 | 说明 |
|---|---|---|
| D1 semantic grader | LLM judge 评估回答质量三维：正确性 / 完整性 / 证据支撑（与规则指标互补，不做对错判定） | ⚠️ 与 D005「规则式指标」冲突，需新增 ADR 修正 D005（judge 仅作质量维度，不替代行为判定） |
| D2 judge 校准 | 抽样 judge 结果与人工标注比对，一致性达标（≥85%）才启用 | 防 judge 不可信 |
| D3 评测集扩充 | 承接方向 B（真实工单数据集评测）产出，将真实样本纳入回归集 | 方向 B 用户云环境进行中 |

## 6. 任务板

| # | 任务 | 验收标准 | 依赖 |
|:--:|------|------|:--:|
| A1 | 失败轨迹采集器：从 eval 逐条结果提取结构化失败样本 | 单测：样本字段完整、错误类型归类正确 | 无 |
| A2 | 反思器：失败样本 → 低预算 LLM 反思 → 经验条目 | 单测：条目 schema 合法、PII 清洗生效、LLM 失败有兜底 | A1 |
| A3 | 经验池：jsonl 落盘 + 容量管理 + 去重 + 检索接口 | 单测：落盘往返、容量淘汰、相似检索命中 | A2 |
| A4 | 检索增强注入：请求 → 相似经验 → 注入 main_agent prompt | 单测：注入格式稳定、不改变决策 owner、开关可关闭 | A3, C1 |
| A5 | 自我改进门控：回归 + 安全硬 gate + 接受/拒绝判定 | 单测：安全下降被拒、效果提升被接受、reward hacking 案例被拦截 | A4 |
| A6 | 自动迭代 loop 脚本：eval → 反思 → 注入 → 回归 → 决策 | 端到端：跑通一轮完整迭代且安全指标持平 | A5 |
| C1 | CrossEncoder rerank 接入检索链路 | 单测 + 检索评测：recall@5 提升或无回退 | 无 |
| C2 | 相关性门控 + 低置信信号 | 单测：低于阈值走澄清/弱证据路径 | C1 |
| C3 | 查询改写（规则 + 低预算 LLM） | 单测：短查询改写稳定、不改写明确查询 | 无 |
| C4 | 检索质量评测集 + recall@k/MRR 基准脚本 | 基准脚本可重复运行，产出基线报告 | C1 |
| D1 | semantic grader（LLM judge 三维质量评分） | 单测 + 抽样人工比对 | 无 |
| D2 | judge 校准报告 | 一致性 ≥85% 才启用 | D1 |
| D3 | 真实工单样本纳入回归集 | 方向 B 产出落地 + 回归通过 | B(云) |

## 7. 量化指标（M）与完成定义（DoD）

| 指标 | 定义 | 目标 |
|---|---|---|
| M1 自我改进有效性 | 门控接受的经验注入使目标错误类型修复率 | ≥ 30%（首轮基线后校准） |
| M2 安全无回归 | 迭代前后注入/Jailbreak/OOS 拒答率与幻觉风险 | 100% / 100% / 100% / 0（硬约束） |
| M3 检索质量 | 检索评测集 recall@5 / MRR | 基线建立后定阈值（参考 0.8/0.7） |
| M4 judge 一致性 | judge 与人工标注一致率 | ≥ 85% |
| M5 端到端 | 一轮自动迭代耗时 + 整体 route 提升 | 全自动可复跑，安全持平 |

**每任务 DoD**：单测通过 + ruff 0 告警 + regression 冒烟通过 + 相关文档（documents/）更新 + git 提交。
**方向 DoD**：全部任务 DoD 达成 + 报告落 `documents/02-review/` + 指标数据落盘 + PROGRESS/DECISIONS 同步。

## 8. 风险与硬约束

| # | 风险 | 约束 |
|:--:|------|------|
| 1 | 经验注入动摇单决策者架构 | 反思器/经验池只产出文本经验，路由决策权严格保留 main_agent（D004） |
| 2 | reward hacking（优化路由牺牲安全） | 安全指标为硬 gate，任何下降即拒绝注入（§3.3） |
| 3 | D005 与 LLM judge 冲突 | 新增 ADR：judge 仅评质量维度，不替代行为判定 |
| 4 | 经验条目泄露工单 PII | 反思器输出必须过 PII 清洗（名字/邮箱/账户号脱敏），只存模式 |
| 5 | 依赖膨胀 | CrossEncoder 复用 sentence-transformers（零新包）；judge 复用现有 LLM 端点；新增依赖需先过 AGENTS 硬约束 7 |
| 6 | LLM 反思/judge 成本 | 反思仅在失败样本触发；judge 抽样评测 |
